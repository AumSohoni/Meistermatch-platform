## Appendix B: Database Schema and ER Diagram

### B.1. Entity-Relationship Overview

```
USERS (1) → (1) PROFILES
USERS (1) → (*) SWIPES
USERS (1) → (*) MATCHES (as employer)
USERS (1) → (*) MATCHES (as worker)
USERS (1) → (*) RATINGS (as rater)
USERS (1) → (*) RATINGS (as ratee)
MATCHES (1) → (1) CHAT_SESSIONS
RATINGS (1) → (1) TRIAL_SHIFTS
```

### B.2. Key Table Definitions (see Chapter 5.9.2 for full schema)

- **users**: Core authentication and consent data; role discriminates employer vs. worker
- **profiles**: Extended user data including trade, certifications (JSONB), location (POINT), ratings aggregates
- **swipes**: Individual swipe events; unique constraint on (user_id, candidate_id) prevents duplicate recording
- **matches**: Mutual right-swipe records; links employer and worker; tracks trial shift status
- **ratings**: 1–5 star evaluations with comments; linked to match; has is_public flag
- **chat_sessions**: Encryption metadata; session keys stored client-side; message pointers

### B.3. Indexes for Performance

- `idx_profiles_trade` ON profiles(trade_specialisation)
- `idx_profiles_location` ON profiles USING gist(location) (PostGIS GiST index for radius search)
- `idx_swipes_user` ON swipes(user_id)
- `idx_swipes_candidate` ON swipes(candidate_id)
- `idx_matches_employer` ON matches(employer_id)
- `idx_matches_worker` ON matches(worker_id)
- `idx_ratings_ratee` ON ratings(ratee_id)
- `idx_ratings_public` ON ratings(is_public)

### C.1. Sample Swipe Endpoint (Node.js/Express)

```javascript
// POST /swipe
// Record a swipe direction from user to candidate
// Auth: JWT required

import express from 'express';
import { authenticateJWT } from '../middleware/auth.js';
import { pool } from '../db.js';

const router = express.Router();

router.post('/', authenticateJWT, async (req, res) => {
  try {
    const { candidate_id } = req.body;
    const direction = req.body.direction; // 'right', 'left', 'up', 'down'
    const user_id = req.user.id;

    if (!['right', 'left', 'up', 'down'].includes(direction)) {
      return res.status(400).json({ error: 'Invalid direction' });
    }

    // Check for mutual match
    const [existingSwipe] = await pool`
      SELECT * FROM swipes 
      WHERE (user_id = ${user_id} AND candidate_id = ${candidate_id})
         OR (user_id = ${candidate_id} AND candidate_id = ${user_id})
    `;

    // Insert current swipe
    await pool`
      INSERT INTO swipes (id, user_id, candidate_id, direction, timestamp)
      VALUES (gen_random_uuid(), ${user_id}, ${candidate_id}, ${direction}, NOW())
    `;

    // Check if mutual match exists
    let mutualMatch = false;
    if (existingSwipe.length > 0 && direction === 'right') {
      // Check if the other user also swiped right
      const otherDirection = existingSwipe[0].user_id === user_id 
        ? existingSwipe[0].direction 
        : /* would need other user's context */;
      // Simplified: mutual match logic implemented in frontend/backend handshake
    }

    // Return match status
    res.json({ 
      success: true, 
      swipeRecorded: true,
      mutualMatch: mutualMatch 
    });

  } catch (err) {
    console.error('Swipe recording error:', err);
    res.status(500).json({ error: 'Internal server error' });
  }
});
```

### C.2. Sample Geolocation Query (PostgreSQL + PostGIS)

```sql
-- Find workers within 30 km of a given employer location
-- Employer location stored as POINT in profiles table

SELECT 
  p.id,
  p.trade_specialisation,
  p.rating_average,
  p.years_experience,
  ST_Distance(
    p.location, 
    (SELECT location FROM profiles WHERE id = $1)
  ) as distance_km
FROM profiles p
WHERE 
  ST_DWithin(
    p.location, 
    (SELECT location FROM profiles WHERE id = $1), 
    30000  -- 30 km in meters
  )
  AND p.trade_specialisation = $2  -- Filter by trade
  AND p.rating_average >= 3  -- Minimum rating filter
  AND p.rating_count >= 3  -- Minimum ratings count
  AND p.gdpr_consent = TRUE  -- Only consenting users
  AND p.role = 'worker';  -- Only worker profiles
ORDER BY distance_km ASC;
```

### C.3. Sample AI Recommendation Preference Update (TensorFlow Lite pseudo-code)

```javascript
// Preference vector: [trade_weight, cert_weight, pay_min_weight, pay_max_weight, distance_weight, rating_weight]
let preferenceVector = new Float32Array(6).fill(0.17); // Initialize uniformly

function updatePreference(swipeDirection, profileFeatures) {
  // Simple gradient descent update
  const learningRate = 0.01;
  
  if (swipeDirection === 'right') {
    // Increase weights for features present in liked profile
    for (let i = 0; i < preferenceVector.length; i++) {
      preferenceVector[i] += learningRate * profileFeatures[i];
    }
  } else if (swipeDirection === 'left') {
    // Decrease weights for features present in dismissed profile
    for (let i = 0; i < preferenceVector.length; i++) {
      preferenceVector[i] -= learningRate * profileFeatures[i];
    }
  }
  
  // Clip to [0, 1] range
  for (let i = 0; i < preferenceVector.length; i++) {
    if (preferenceVector[i] < 0) preferenceVector[i] = 0;
    if (preferenceVector[i] > 1) preferenceVector[i] = 1;
```

- 2 SME employers (construction companies, 10–50 employees each)

1. Register and complete onboarding flow (target: < 5 minutes)
