[508] (NONE) 5.4.2. Mutual-match algorithm
[509] (NONE) Algorithm: mutual_match(user_id, candidate_id)
[510] (NONE) 1. Check if both users have swiped right on each other:
[511] (NONE) - Query DB: SELECT * FROM swipes
[512] (NONE) WHERE (user_id = A AND candidate_id = B AND direction = 'right')
[513] (NONE) OR (user_id = B AND candidate_id = A AND direction = 'right')
[514] (NONE) 2. If both right-swipes exist AND not already matched:
[515] (NONE) - Insert record INTO matches(user_id=A, candidate_id=B, matched_at=NOW())
[516] (NONE) - Unlock chat functionality for both parties
[517] (NONE) - Send push notifications to both users
[518] (NONE) 3. If only one right-swipe:
[519] (NONE) - Store the swipe for future reference
[520] (NONE) - Do NOT unlock chat
[521] (NONE) - Continue swipe feed
[522] (NONE) 4. If no right-swipes:
[523] (NONE) - Return to step 1 on next profile presentation

[530] (NONE) 5.5.1. Preference learning model
[531] (NONE) The system learns user preferences from swipe behavior to improve match quality over time.
[532] (NONE) **Feature vector per profile**: `[trade_encoded, years_experience, certification_count, pay_min, pay_max, location_distance, rating]`
[533] (NONE) **Preference vector per user**: Updated after each swipe using simple gradient descent:
[534] (NONE) - If swipe right → increase weight for matching features
[535] (NONE) - If swipe left → decrease weight
[536] (NONE) **Algorithm**:
[537] (NONE) 1. **Content-based filtering**: Match profiles where `trade_specialisation` matches user's most-swiped trade, and certification overlap > 50%
[538] (NONE) 2. **Collaborative filtering**: Anonymised swipe-pattern analysis – if users with similar swipe history to User X also swiped right on Candidate Y, su
[539] (NONE) 3. **Hybrid approach**: 70% content-based + 30% collaborative filtering for new users (cold start)
